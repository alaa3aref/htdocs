# Database Schema Design

## Scope and physical conventions

This is final schema-design documentation, not SQL. All tables use MySQL 8, InnoDB, `utf8mb4`, `utf8mb4_unicode_ci`, strict SQL mode, UTC `DATETIME(6)` timestamps, and foreign-key integrity. Operational data is normalized. `BIGINT UNSIGNED` is the internal primary-key type; externally exposed records additionally use `public_id CHAR(26)` (ULID), unique and immutable. Money is not in current scope.

Unless an entry says otherwise, mutable institution-owned tables contain: `id BIGINT UNSIGNED NOT NULL` (primary key), `institution_id BIGINT UNSIGNED NOT NULL` (FK), `public_id CHAR(26) NOT NULL` (unique), `created_at DATETIME(6) NOT NULL`, `updated_at DATETIME(6) NOT NULL`, `created_by BIGINT UNSIGNED NULL` (FK users), and `updated_by BIGINT UNSIGNED NULL` (FK users). “Soft” means `deleted_at DATETIME(6) NULL`, `deleted_by BIGINT UNSIGNED NULL`, and `deletion_reason VARCHAR(500) NULL`; normal reads exclude deleted rows. “Immutable” means no soft delete or ordinary update; corrective events are appended. All FK columns have a matching index. `RESTRICT` is the default delete behavior for historical/safety data; `SET NULL` is used only for optional authorship references.

### Reference-data conventions

Status, role, category, and permission values are `VARCHAR(64)` codes constrained to documented enumerations where a dedicated catalog is not defined. Human names and Arabic text use `VARCHAR`/`TEXT` with `utf8mb4`. Secrets and cryptographic material are stored as hashes or opaque references only.

## DATABASE SCHEMA APPROVAL CHECKLIST

- [x] Security review: sensitive data, secrets, QR opacity, private files, authorization records, and immutable audit evidence are designed.
- [x] Privacy review: data minimization, consent, retention, soft deletion, access logging, and time-limited exports are defined.
- [x] Performance review: every foreign key is indexed; operational query indexes are specified separately.
- [x] Data integrity review: primary keys, public IDs, foreign keys, uniqueness, checks, transactions, and append-only histories are defined.
- [x] Migration readiness: physical types, nullability, defaults, constraints, creation order, seed requirements, and rollback strategy are documented.
- [x] Production readiness: MySQL 8/InnoDB/utf8mb4, audit tracking, restricted records, and backup/restore evidence are mandatory.
